# ② skill-gap — 能力地圖

**形態**：Web app，分兩期：v0 零後端 → v1 LLM API + Google 登入 + 獨立資料庫
**階段**：我有什麼／缺什麼 ／「我大概知道方向，但不知道自己現在有什麼」
**架構重量**：v0 零後端；v1 是**全平台唯一的重架構產品**，也是唯一的留存機制
**UI 基底**：繼承 career-town 既有能力地圖 UI（列表卡 + 單卡 modal），本文件 §UI 為準

## 目的

讓使用者把「我好像會一點文案、辦過活動」變成一張結構化的能力地圖：

- 每項能力有**四階精熟度**（見下），綁**佐證**（哪段經歷證明的）與**學習感受**
- 對照目標方向的市場要求，產出**差距**與**學習資源**（lazy，見 §想加強）
- 產出一張**可截圖的能力地圖**——整個平台最核心的視覺資產

### 精熟度四階（全平台統一命名）

| 階 | 名稱 | 定義 |
|---|---|---|
| 0 | 待學習 | 尚未能穩定完成 |
| 1 | 初學 | 可在指引下完成 |
| 2 | 熟練 | 可獨立完成 |
| 3 | 精通 | 可穩定交付並協助他人 |

## 三條 governance 紅線（兩期都適用）

1. 自評、佐證、市場要求是三條獨立的 lane，永不互相推導（governance §8）。UI 文案沿用 career-town 版：**「自評與證據會分開顯示，不互相代填」**、**「沒有已確認證據不會降低自評，只表示履歷還不能引用這項能力」**
2. 沒有佐證的能力顯示為「自評」，有佐證的標明來源經歷——視覺上明確區分
3. 差距呈現為「可以補」，永不呈現為「你不行」

## UI/UX 規格（v0 / v1 共用同一個殼）

### 版面：左對話、右地圖

```
┌────────────────────┬──────────────────────────┐
│  對話區             │  能力地圖                  │
│  （盤點引導）        │  頂部敘事統計 + 能力卡列表    │
│                    │  卡片隨對話進度長出           │
└────────────────────┴──────────────────────────┘
（手機：上下堆疊，對話在上，地圖出現新卡時 toast 提示可下滑查看）
```

兩版只換對話來源，右側與所有卡片互動完全相同：

| | 左側對話區 | 右側卡片出現時機 |
|---|---|---|
| **v0** | 腳本式引導問答（純前端，不叫 API）→ 結尾「複製這段去問 ChatGPT/Claude」→ 貼回 AI 回覆 | **貼上瞬間**逐張動畫長出（v0 的關鍵 moment，動畫必須做） |
| **v1** | 站內真實 API 對話 | 講到哪長到哪（邊對話邊 streaming 解析） |

### 頂部統計：敘事反轉（反焦慮鐵律）

**禁止**並列裸數字（「待學習 7・初學 8・熟練 3・精通 0」）。改為一句敘事 + 次要明細：

> **你已經有 11 項能力在路上**（熟練 3、初學 8），還有 7 項等你決定要不要碰。

**預設排序：精通 → 熟練 → 初學 → 待學習。** 強項在最上面，第一眼是「我原來會這些」。篩選 chip 保留（全部／各階／想加強中）。

### 能力卡

- 列表卡：階段徽章 + 能力名 + 自評摘要一行 + 證據狀態一行 +「+ 想加強」按鈕（沿用現有 UI）
- **顆粒度規則（寫入 skill output contract）**：一張卡 = 一個可獨立評級的能力。「解釋、寫作、簡報、語言溝通」這類叢集**不得**成卡——叢集只能當分組標題，卡片可帶語境括號（例：「簡報（課堂／提案場合）」）
- 卡片生命週期：AI 提出 → **pending 灰卡**（虛線框，標「AI 建議，點擊確認」）→ 使用者在 modal 確認精熟度 → 上色為正式卡。未確認的卡不計入頂部統計

### 單卡 modal（沿用截圖二結構，補一段）

1. 目前自評（AI 的線索摘要，標明推論來源）
2. 四階精熟度選擇（2×2 卡片，點選即確認）
3. 已確認證據區（藍底；空時顯示既有文案）
4. **（新增）學習資源區**：僅在此能力被按過「想加強」後出現，內容見下

### 「+ 想加強」＝ 資源生成的唯一入口（lazy）

- 確認精熟度後**不**自動生成資源。只有按「+ 想加強」才生成該項的學習資源
  - v1：即時呼叫 API 生成
  - v0：產生針對該能力的資源查詢 prompt（一鍵複製 → 貼回結果進 modal）
- **全域上限 3 項**。加第 4 項時提示：「你已經有 3 項在加強中——先完成或放下一項，再加新的。」這是產品立場（3 項是計畫，18 項是壓力），不是技術限制
- 資源卡固定三件事，不給課程大雜燴：
  1. 一個免費資源（連結）
  2. 一個 30 分鐘內可完成的行動
  3. 一句「怎麼算補上了」——完成後回填為證據、升精熟度的驗證條件

### 下一步導引

地圖有 ≥ 5 張已確認卡後，頁面底部出現：「地圖有了——把有證據的經歷寫成履歷」→ resume-composer，附「複製給履歷生成器」文字塊（僅含已確認、有佐證的項目）。

## v0（零後端，先上線）

### 流程

1. **帶入方向**：從 localStorage 讀 `ct_result`；沒有就讓使用者選／填 1–2 個方向
2. **左側腳本引導**：對話式表單問「做過的事」（大輸入框，用講的）；右側同步出現灰色佔位卡示意
3. **結尾組出 prompt**（含 governance + 方法論 + 顆粒度規則 + 市場要求查證指示），一鍵複製
4. **貼回** AI 回覆 → 容錯解析 → 能力卡逐張長出（pending 灰卡）
5. 使用者逐卡確認精熟度 → 頂部敘事統計成形 → 存 localStorage `sg_map`
6. 「想加強」走複製貼上迴路（見上）

### AI 回覆的解析格式

要求 AI 用固定標題 Markdown（不是 JSON），**每區塊一個可獨立評級的能力**：

```
### 能力：簡報（課堂／提案場合）
自評線索：（引用使用者原話）「系學會成發是我上台報告的」
建議精熟度：初學
學習感受：有興趣
差距：目標「數位行銷實習」常要求對客戶提案，你的經驗在校內場合
```

前端逐區塊解析，抓到幾塊畫幾塊；解析失敗的區塊以純文字卡呈現，**永不空白畫面**。AI 給的「建議精熟度」只作為 modal 內的預選提示，**確認權在使用者**。

### v0 驗收

- 不登入、不裝任何東西，10 分鐘內從空白走到一張可截圖的能力地圖
- 頂部第一眼是「你已經有 N 項在路上」，不是缺陷計數
- 每張卡能看出「自評」還是「有佐證」；未確認的 AI 建議卡視覺上明顯是灰的
- 「想加強」超過 3 項會被擋
- AI 回覆裡出現使用者沒說過的數字，解析層丟棄該佐證並標示「待確認」

## v1（重架構：LLM API + Google 登入 + DB）

**觸發條件**：Wave 4（v0）完成即開工。

原設計是「v0 完成率 ≥ 20% 才開工」，但平台改為全部完成後才發布（見 `PLATFORM_PRD.md` §7），發布前不會有任何真實使用數據，此門檻無法評估，故取消。代價是這個唯一的重架構產品在無使用者驗證下投入——這是知情的取捨。

因此 v0 的地位更重要：它不只是過渡版本，而是 v1 的規格草稿與永久的降級路徑。v0 的欄位、解析格式與地圖視覺一旦定案，v1 直接沿用，不重新設計。

### v1 相對 v0 的增量

| 增量 | 說明 |
|---|---|
| 站內對話 | 左側變成真的 API 對話，卡片邊講邊長（streaming 解析同一套格式） |
| Google 登入 | OAuth，只取 email + 基本 profile |
| 資料庫 | 地圖、佐證、想加強清單跨裝置保存；**全平台唯一的回訪理由** |
| 版本快照 | 每次更新留快照，呈現「三個月來的變化」——第二個可截圖資產 |
| 想加強追蹤 | 3 項行動可勾選完成 → 引導回填佐證 → 升精熟度（升級動畫值得做，這是留存的獎勵時刻） |

### 技術棧（建議）

- Next.js（沿用 career-test 既有棧）+ Cloudflare Pages/Workers（已有 wrangler 經驗）
- DB：Supabase（Google OAuth 現成）或 Cloudflare D1
- LLM：Haiku 級即可；API key 走後端 proxy，前端永不見 key

### 資料模型（最小）

```
users(id, email, created_at)
skill_maps(id, user_id, direction, created_at)          -- 一人可多方向
skills(id, map_id, name, context_note, level(1-4), feeling,
       status(pending|confirmed), focus bool)            -- level 對齊 skill schema 1-4；focus = 想加強
focus_actions(id, skill_id, resource_url, action_text, done_criteria, done bool)
evidences(id, skill_id, raw_text, source_note, confirmed bool)
map_snapshots(id, map_id, payload_json, created_at)
```

沿用 pending/confirmed 生命週期：AI 建立的 skill 與 evidence 一律 pending，使用者確認才轉正；`focus=true` 的 skill 全 map 上限 3。

### 成本與濫用防護（上線前必須有）

- 每帳號每日 LLM 呼叫上限（建議 20 次）；「想加強」資源生成計入
- 單次對話 token 上限；超過引導回 v0 複製貼上模式
- 月度 API 預算告警，超過即全站降級 v0 模式——**v0 永遠保留，它就是 v1 的 fallback**

### v1 驗收

- 登入 → 對話中卡片即時長出 → 確認 → 入庫 → 換裝置看得到同一張圖
- 一個月後回來看得到變化快照
- 勾完一項想加強行動 → 被引導回填佐證 → 精熟度升級有明確回饋
- API 被打爆時自動降級 v0，不白屏、不噴錯
