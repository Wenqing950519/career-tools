# ⑤ offercheck — 該不該去

**形態**：純 skill（已完成 ✅）
**階段**：該不該去 ／「我拿到 offer 了，但不知道該不該去，還是要快逃」
**架構重量**：零後端。本文件只記錄整合與行銷定位，功能不動

## 現狀

`skills/offercheck/` 已具備：評分方法論（scoring.md）、證據圖（evidence.md）、report schema + validator、HTML 報告 renderer。是全平台完成度最高、唯一有「可截圖產出」的 skill——其他產品的產出形態都在向它看齊。

## 要做的三件事（都不是改功能）

### 1. 入口頁面改造（依 vibe-hub 順序原則）

現行頁面直接放「複製範本／Prompt 產生器」，缺少讓人想用的前置內容。重排為：

1. **處境開場**：「你手上有兩個 offer，三天內要回覆。你問了五個人，得到五種答案。」
2. **免費給完的內容主體**：從 scoring.md / methodology.md 萃取〈選 offer 該看的檢查點〉清單，人讀版、可截圖、可被搜尋——這是本產品的行銷素材與 SEO 入口
3. **一份真實範例報告**（公司匿名化）：讓人先看到成品長什麼樣
4. **然後才是** Prompt 產生器（現有的表單保留）

### 2. 與 opportunity-catch 的接口

opportunity-catch 清單中每個機會附「用 offercheck 評估這個」素材（公司 + JD 摘要 + 連結）→ 直接可貼入 offercheck 的產生器或對話。入口頁的產生器支援 URL 參數預填（`?company=…`）作為未來一鍵串接的鉤子。

### 3. 敘事對齊

全平台文案中，offercheck 的角色是主線終點：「走到這裡，你已經從『不知道自己想做什麼』走到『有依據地做決定』。」完成頁導引回入口頁：「下一個階段的你，會再回來。」（例如下一輪找機會、或帶著新經歷回 skill-gap 更新地圖）

## 驗收

- 入口頁不看任何工具說明，先能讀完檢查點清單並想截圖
- 範例報告點開即看，不需要先填任何表單
- 從 opportunity-catch 的產出複製素材貼入，一輪對話啟動背調
