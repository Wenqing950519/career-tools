# Composition Method

## Eligible claims

**Injected mode** — use only user-selected confirmed experiences. A pending proposal, rejected record, self-rating, course title alone, agent hint, or job-description statement is not eligible personal evidence.

**Standalone mode** — use only experiences the user affirmed in conversation per `interview-method.md`. An unaffirmed draft, a revised draft awaiting re-confirmation, and anything the user only implied are all ineligible.

## Drafting

Write each entry with a supported role or contribution, action or method, and observable result when available. Preserve modest verbs and team attribution. Do not manufacture a metric to make a bullet look complete; the quantification ladder in `interview-method.md` governs every number that appears.

The optional job description may influence ordering and vocabulary only when the resulting wording remains true to confirmed evidence. Never copy a requirement into the resume as an achievement.

## Traceability

Each experience entry carries the contract's singular `sourceId`: an injected confirmed evidence ID in injected mode, or the `chat-N` ID assigned at the moment of the user's affirmation in standalone mode. Together these identifiers form the draft's source trace. If a claim needs multiple sources, split the claim into traceable entries or keep it out.

Unknown personal details remain `null` in the exchange draft and appear in envelope `unknowns`. Do not use plausible placeholders that resemble facts.

## Category assignment

`category` uses exactly one of 實習經歷｜實踐經歷｜校園經歷.

- 實習經歷 — internships, part-time and full-time work, contract work.
- 實踐經歷 — personal and team projects, competitions, research, freelance and volunteer work outside school organizations.
- 校園經歷 — student government, clubs, course-based work, campus events.

When an episode plausibly fits two categories, place it where a reader would look for it and note the choice. Do not duplicate one episode across categories.
