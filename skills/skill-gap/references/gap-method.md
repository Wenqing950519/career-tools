# Gap Method

## Proficiency scale

The 1–4 self-rating has one fixed public naming across the whole platform. Always use these names in user-facing text; the integer is for the machine block only.

| level | 名稱 | 定義 |
| --- | --- | --- |
| 1 | 待學習 | 尚未能穩定完成 |
| 2 | 初學 | 可在指引下完成 |
| 3 | 熟練 | 可獨立完成 |
| 4 | 精通 | 可穩定交付並協助他人 |

Never invent an intermediate level, a decimal, or a percentage. Never rename these tiers.

## Capability granularity

One capability = one thing a person could plausibly rate differently from its neighbours.

- Split clusters. 「解釋、寫作、簡報、語言溝通」 is four capabilities, because a user can be 熟練 at 簡報 and 待學習 at 寫作. Emitting it as one unit makes the rating meaningless.
- A capability may carry a short context in parentheses when the context changes the rating: 「簡報（課堂／提案場合）」、「英文（讀寫／口說）」.
- Cluster names may be used as a grouping heading above several capability blocks. They may never be a capability block themselves.
- Prefer 8–20 capabilities. Below 8 the map is not actionable; above 20 the user cannot process it.

## Requirement evidence

Prefer injected role requirements. When research is necessary, use a small current sample of primary employer descriptions or authoritative occupational documentation. Record the source and observation date in the human explanation. External requirements are not facts about the user.

## Comparison lanes

For each capability state:

- market requirement and source confidence;
- explicit self-rating from 1 to 4, or a clearly labelled unconfirmed suggestion;
- confirmed evidence IDs and what they actually demonstrate;
- unresolved boundary;
- minimum validation action.

Do not infer a self-rating. Do not count a course name as performance evidence. Do not treat one listing as the whole market.

## Strength-first framing

The user arrives anxious. Ordering and wording change how the same data lands.

- Order capability blocks 精通 → 熟練 → 初學 → 待學習.
- Open the response with what the user already has, stated as a count of capabilities in progress, before naming any gap.
- Never open with, or lead a section with, a deficit tally.
- Write every gap as something addable ("目標職缺常要求 X，你目前的經驗在 Y 場合"), never as a personal deficiency ("你缺乏 X").
- A missing evidence link lowers nothing. State plainly that it only means the resume cannot cite that capability yet.

## Priority

Use `high`, `medium`, or `low` only as an action order, not a score. Prioritize hard prerequisites, capabilities shared across several target tasks, and gaps that can be cheaply tested. Explain the priority inside `assessment_note`; do not add a new data field.

An action should take 30–90 minutes when possible, produce an observable artifact, and test the capability rather than merely consume advice.

## Learning resources

Do not generate learning resources for every capability. Resources are produced only for a capability the user explicitly asks to strengthen, and at most three at a time. When asked, give exactly three things for that one capability:

1. one free resource with a link;
2. one action completable in 30 minutes;
3. one observable completion criterion that could later become evidence.

Never output a course catalogue, a multi-week curriculum, or a reading list.
