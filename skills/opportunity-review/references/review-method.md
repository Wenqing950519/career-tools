# Review Method

## Hard constraints first

Check only explicit non-negotiables such as location, schedule, work authorization, deadline, compensation floor, language, eligibility, or conflict dates. Use `pass`, `fail`, or `unknown` in the human explanation. A preference is not a hard constraint unless the user said so.

## Independent axes

- **Direction relevance:** overlap with current exploration directions, without treating attention as fit.
- **Evidence opportunity:** likelihood of producing bounded, explainable evidence based on stated duties.
- **Operating conditions:** supervision, scope, schedule, and resources only when stated.
- **Unknown risk:** missing facts that could change the pending judgment.

Do not average axes. Do not treat attractive wording as proof. Do not infer that a requirement is a user capability or deficit.

## Judgment mapping

Use the existing bucket as a pending action proposal:

- `focus`: apply;
- `explore`: conditionally apply or clarify through publicly available information;
- `watch`: not now because material facts are unknown or timing is premature;
- `exclude`: do not apply because an explicit hard constraint fails or the stated opportunity is outside scope.

The bucket is reviewable and never a final automated recommendation.
